# Fix UDS Client FreeRDP 3 Keyboard Error on Arch Linux / CachyOS

This guide explains how to fix a FreeRDP 3 compatibility issue when connecting to a virtual machine through **UDS Client 4.0.0** on Arch Linux-based distributions such as CachyOS.

## 1. Issue

After installing UDS Client from the `.tar.gz` archive and installing all required dependencies, the client launches but fails to open the remote VM.

Checking the system logs with:

```bash
journalctl -r -l --no-pager
```

Shows the following error:

```text
[ERROR][com.freerdp.client.common.cmdline]
[parse_command_line]: Command line parsing failed at 'kbd' value '0x00000410' [-1002]
```

FreeRDP then displays its command-line help instead of establishing the RDP connection.

## 2. Explanation of the issue

The problem is caused by a **compatibility difference between FreeRDP 2 and FreeRDP 3**.

UDS Client generates an RDP command containing the keyboard layout parameter using the older FreeRDP syntax:

```bash
/kbd:0x00000410
```

However, FreeRDP 3 expects the keyboard layout to be specified using:

```bash
/kbd:layout:0x00000410
```

Here, `0x00000410` identifies the Italian keyboard layout. The problem is not the keyboard layout itself, but the argument syntax.

Since CachyOS and other rolling-release Arch-based distributions use newer versions of FreeRDP, the command generated by UDS Client may fail during argument parsing.

## 3. Solution

The solution is to create a small compatibility wrapper that automatically converts the old keyboard parameter into the FreeRDP 3 format.

This avoids modifying UDS Client's files or downgrading FreeRDP.

### Step 1 — Create the wrapper

Open a new script:

```bash
sudo nano /usr/bin/udsrdp
```

Paste the following code:

```bash
#!/bin/bash

args=()

for arg in "$@"; do
    case "$arg" in
        /kbd:0x*)
            arg="/kbd:layout:${arg#/kbd:}"
            ;;
    esac

    args+=("$arg")
done

exec /usr/bin/xfreerdp3 "${args[@]}"
```

The script checks the arguments passed by UDS Client, replaces the outdated keyboard syntax, and forwards everything to FreeRDP 3.

### Step 2 — Make the script executable

Run:

```bash
sudo chmod 755 /usr/bin/udsrdp
```

### Step 3 — Test the wrapper

Run:

```bash
/usr/bin/udsrdp /kbd:0x00000410
```

FreeRDP may report that a server address is missing, which is expected.

The important part is that the original keyboard parsing error should no longer appear.

### Step 4 — Launch your VM

Restart UDS Client and try connecting to your virtual machine again.

If UDS Client is configured to use `/usr/bin/udsrdp`, the wrapper will automatically correct the keyboard argument and allow FreeRDP 3 to process it.

If the same error persists, verify that UDS Client is actually invoking the wrapper.

---

## Notes

- **Tested environment:** CachyOS, UDS Client 4.0.0, FreeRDP 3.
- The wrapper works for keyboard layout arguments matching `/kbd:0x*`, not just the Italian layout.
- It does not change any other FreeRDP arguments.
- The fix assumes FreeRDP 3 is installed at `/usr/bin/xfreerdp3`.
- Other compatibility issues may exist depending on the UDS Client version and server configuration.

**Summary:** UDS Client may generate FreeRDP 2 keyboard arguments that FreeRDP 3 cannot parse. A simple `/usr/bin/udsrdp` wrapper translates the outdated syntax, allowing the RDP connection to proceed.
